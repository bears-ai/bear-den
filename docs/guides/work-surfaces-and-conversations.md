# Work surfaces and conversations

A **work surface** is a durable resource/environment; a **conversation** is a canonical owned transcript/source, not a transient client session. Current working-tree WIP is described in [Bear memory and hats](../topics/bear-memory-hats.md), not yet validated in the latest rebuilt image.

## Keep the boundaries separate

| Boundary | Owner/meaning |
| --- | --- |
| Bear | Durable identity and Bear-wide settings. |
| Hat | Bear-owned responsibility/identity, curated-memory audience, and applicable bounded grants. |
| Conversation | Canonical human owner, transcript, model override, source-local notes, and immutable hat binding. |
| Work Job/run | Exact approved assignment, eligible Job hat, assigned surfaces, and run-local notes. |
| Client session/armature | Live authenticated harness, reported roots/tools, availability, and permission obligations. |
| Work surface/Connection | Resource, environment/network ceilings, and separately scoped credentials; no independent hat grant. |

Every ordinary conversation, Job, and run needs a **real hat**, even with zero hats. A Bear with no hats needs explicit setup, not an autogenerated default. Old unbound threads are owner/admin read-only history; ownerless history is admin-only. Imported settings/records do not fabricate ownership, grant a hat, or automatically promote memory.

## Starting an editor conversation

The Bear-level token authenticates the human and armature, not a stance or hat. A pending IDE session does not materialize durable `den-conv-*` until hat admission succeeds. An explicitly configured IDE default selects a real Bear-owned hat; otherwise choose with `/hat <name or UUID>` before productive interaction. Bare `/hat` lists choices. Reconnect retains the canonical binding; admin transcript inspection is not execution as another owner.

Channel conversation, browser task controls, and connected armature are distinct verified origins. Browser task capability does not imply a local harness. Disconnect/governance can narrow local tools without changing memory ownership or turning a conversation into a Work Job. Inference, continuations, tool-result recording, and direct dispatch recheck live canonical actor/source/hat and exact Work eligibility.

## Resources and execution

Prefer **“Start a conversation with this repository”** over an implicit mid-thread checkout. Workspace roots and primary-resource resolution must come from trusted client/canonical state, not casual model prose. A resource selection does not grant arbitrary mutations, credentials, network, or access to another conversation's notes. Future mobile/server-sandbox integrations must define their verified harness and source boundary rather than claiming `pair` authority from a label.

Work derives its hat from the exact eligible Job, never the IDE default. It must cover assigned surfaces and current Work eligibility. Enabling Work on a populated hat requires reviewing its full historical memory and identity; each later run separately rechecks Job/run/surface eligibility. Neither enablement nor a resource assignment starts a run.

## Memory, tools, and settings

Ordinary memory is own-source notes + authorized selected-hat knowledge + Bear `core/`. Legacy profile-local history is restricted admin/review data, not a no-hat fallback. Pair Plan/shared work-surface scaffold model tools are retired; historical rows/records are not live planning/shared-write authority.

Admin stance detail/configuration/provisioning is retired; `/models` is Bear-wide. Initialization never creates/refreshes a profile registry. Managed compilation emits bound base/platform modes independently of legacy contracts; origin and canonical source own defaults, control, and compaction. Runtime-context labels retain historical schema encoding only, not configurable trust stances.

Hat action/resource enforcement is **partial**: supported Den web, exact-root editor filesystem reads, and upgraded sandbox egress. Broader Den effects/catalogs and other bounded persistent client choices remain next. No ordinary Legacy network/Cargo path exists; hat-bound Cargo preparation is denied pending a grant-enforced cache. See [Gate 0A](../roadmap/HATS_AND_SESSION_MEMORY_BOUNDARIES_PLAN.md#gate-0a--hat-owned-tool-and-network-permissions-partial-cutover-exit-pending), not a claim of complete `HatGrantResolver`.

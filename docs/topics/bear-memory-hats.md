## Current behavior in this branch

### Admission and history

- Every ordinary conversation, Job, and run requires a **real Bear-owned hat**, including on a Bear with zero hats. A conversation must have its canonical owner/hat binding; Work requires the exact live, uncancelled run and an eligible Job hat covering its assigned surfaces. A zero-hat Bear cannot execute through a legacy fallback.
- Browser and BearWire admission fail before ordinary message/turn persistence or Work checkout/provisioning when these bindings are absent or ineligible. Old unbound transcripts remain owner/admin-readable history, not writable ordinary sessions; NULL-owner history is admin-only. An admin's right to inspect another person's history does not grant execution as its owner.
- A pending IDE session does not create a durable `den-conv-*` conversation until hat admission succeeds. An explicitly configured IDE default may select a real hat; `/hat` lists or selects a Bear-owned hat before productive interaction. Reconnect retains the canonical binding. No default hat is fabricated, imported settings do not manufacture one, and no records or permissions are automatically promoted into one.
- Source admission precedes every production inference, including all continuations; client tool-result recording, compacted-output reads, and direct Den tools also recheck the live canonical actor, immutable source, hat, and exact Work run where applicable. Cached labels, a session ID, caller-supplied origin, or an admin-visible transcript cannot substitute for admission. Source checks do not imply every effect has complete hat-action/resource filtering.
- Conversations/transcripts, client sessions, Docket tasks/Jobs, and memory have distinct canonical owners. Model replay and human history are separate projections; human history excludes diagnostic/model-only records. Historical session-ID collisions and ownerless records remain quarantined, not inferred into ownership. Same-creator cross-conversation generic artifact isolation and remaining session-only joins still need audit.

### Identity, settings, and runtime context

- Bear-admin stance detail/configuration/provisioning is retired. `/bear/{slug}/models` owns named Bear model configurations, the Bear default, budget, loop control, and Bifrost key settings, not per-stance rows. Admin per-profile model and profile-registration routes are gone. Native initialization opens memory, ensures the runtime plan, and compiles managed configuration; it never creates or refreshes a stance/profile registry.
- Historical profile model/loop rows, contracts, settings, and audit encodings remain historical inspection data, not live overrides. Ordinary model selection uses explicit conversation pins, canonical hat configuration references, and Bear/deployment defaults, in that order. Runtime defaults, loop control, continuation, and compaction policy derive from verified execution origin and current governance, never a stale profile override.
- Managed compilation produces the bound Bear-wide base and platform-owned interaction modes only. Bound base parsing is independent of legacy role contracts and their metadata. No production inference selects a role prompt or role contract. Turn assembly selects the current hat identity from its canonical source and validates compiled source versions; it does not copy a historical stance contract into a hat. Hat names and explicitly authored short summaries are directory data, not permissions. Full identity belongs only to the selected hat; purpose remains admin-facing.
- The Rust types `TrustProfile` / `BearProfile` / `BearStance` and their aliases are removed; derived runtime-context metadata uses `RuntimeContextLabel`. Its five source-kind labels describe channel conversation, armature conversation, Job run, curation operation, and observation operation. Historical `chat/pair/work/curate/watch` encoding remains for schema/audit compatibility. A label cannot reconstruct authority or configure a stance; browser task sessions remain a distinct verified origin despite sharing the historical `pair` encoding.
- Effective capability ceilings come from verified `TurnExecutionOrigin` and governance. Channel conversations have no local armature tools; browser task controls do not invent an armature; disconnected or restricted-governance turns cannot borrow connected-client tools. Typed descriptor audiences and connected-armature filtering apply to native rosters and dispatch. The common hat-grant/resource resolver is still partial.

### Bear-scoped gateway availability and embedding authentication (2026-10-10)

**Current code/test follow-on; not deployed:** Den's selectable model table supplies product metadata and capability facts, not proof that a Bear can execute a model. Web/ACP choices now intersect that metadata with the Bear's authenticated Bifrost catalog. New configuration/default/hat/pin choices and existing-Bear legacy edits validate a fresh catalog before writes; no global, static, or cached positive result authorizes a new selection. Stored unavailable configurations remain inspectable and unchanged, and clearing references/pins remains possible for repair. New-Bear setup treats a submitted model as an unverified proposal: it provisions the new Bear's key, verifies the choice with that key, and only then saves the active default and continues initialization. Failed setup compensates only its own untouched new root; intervening work blocks cleanup and the response identifies the saved Bear rather than encouraging duplicate creation.

Canonical-source admission and primary-model preflight now precede native context assembly/optional recall and transcript writes. Browser sends and BearWire preflight also reject a known missing/unavailable model or missing/rejected key before turn-side effects. Execution distinguishes **an existing canonical explicit pin during a genuine catalog outage** from **a new selection**: continuity may attempt that same pin using credential-matched cached transport, or Responses when no cached transport is known. It never substitutes another model and never overrides a successful catalog denial, missing key or rejected key. Preview labels such a retained pin `unverified`, not available; fresh choices remain empty during the outage. Provider/catalog state can change after any check; this is preflight and recovery, not an availability lease or inference-success guarantee.

`ModelAvailabilityFailure` preserves structured reason through runtime/HTTP/BearWire boundaries. Public errors include a checked model reference, actionable recovery and the request reference, never provider bodies, credential values or endpoint URLs. Codes are `model_missing` / `model_unavailable` (HTTP 400), `virtual_key_missing` / `virtual_key_rejected` (409), and `catalog_unavailable` (503); key setup failures are not mislabeled as human login or membership failures. For the reported `openai/gpt-6-sol` case, the diagnostic states that the selected model is missing from this Bear's Bifrost catalog and directs the human to choose an available model in Models or repair Bifrost access.

Catalog requests disable redirects and mark the virtual-key header sensitive. A per-Bear refresh queue, persistent generations and canonical-credential rechecks prevent old positive responses or rejected/rotated credentials from repopulating usable cache authority. Legitimate concurrent checks still perform fresh authenticated requests and converge without inventing a catalog outage.

All Bear-scoped embedding searches and indexing now resolve the Bear's current server-side virtual key per operation and send `x-bf-vk`, with no global/admin key fallback. Missing/invalid credentials stop before HTTP. Optional recall still degrades rather than rejecting chat; indexing failures remain safely recorded. Embedding transport/status failures discard provider bodies, inputs, credentials and URLs, and embedding redirects are disabled. No key enters model context or Bear memory through this path.

### Memory and publication

- Per-Bear SQLite owns canonical memory. Ordinary tools and turn-start projection use only own-source private notes, authorized selected-hat knowledge, and Bear-wide `core/`, with canonical scope/access checks. There is **no ordinary Legacy profile-memory path**, even on zero-hat Bears. Old profile-local records remain restricted historical admin/review data with unverified ownership; paths, imported IDs, and session-like strings do not prove a source owner.
- Bound prompt-memory reads select Bear-wide and exact-client-session blocks; writes/patches are confined to the current session. Historical profile/work-surface blocks do not widen ordinary context. Opaque caller runtime text cannot replace Den's compiled supplement.
- Member library feed/search/browse/direct-ID/history expose only current authorized hat/core records, not raw notes. Semantic recall filters candidates, rechecks current SQLite scope/lifecycle/access, and reconstructs text there; stale vector payloads confer no access. Recall indexes only eligible current `core/` and hat records; source-local and profile-local records are **never indexed**, even with zero hats. Stale legacy derived-point cleanup is retried before embedding, without changing canonical historical SQLite. Profile-string recall APIs are removed. Recall can disclose reviewed text to the configured embedding provider and stores derived passages/vectors in Qdrant; network, privacy, and usage costs apply. Unavailable recall falls back to curated keyword search. Derived cleanup neither promotes historical records nor grants ordinary legacy-memory access.
- Owners can inspect their source's private conversation notes separately from the shared library; Bear-admin transcript inspection alone does not grant that owner-only view. Raw entity/reflection/proposal inspection remains admin-only until provenance is scoped.
- Source→hat and hat→`core/` publication require verified provenance and newly authored shareable content, with explicit audience acknowledgement and optimistic current-head checks. The source stays private/unchanged. Explicit legacy review may cite an eligible historical record as unknown-owner provenance; it does not import it as ordinary memory, assign ownership, or automatically promote it. The model-facing legacy core-update tool and autonomous legacy core-action proposals are retired.
- Automatic hat sharing starts off. When enabled, Curate can rewrite a verified conversation-local note into knowledge for every authorized wearer, including eligible Jobs. Source, creator membership, hat, proposal, and opt-in are checked before synthesis and again at publication. Invalid/provider-failed synthesis stays private/pending; typed synthesis failures have durable delayed retries and bounded recovery, with recurring model-call cost. Curation is tool-free and does not certify privacy or turn content into trusted instruction. Live Bifrost synthesis/background delivery remain unvalidated.
- Old Pair Plans and shared work-surface scaffold **model tools** are retired. Historical rows/records are not live planning or shared-memory write authority. Current task/Docket state remains separate from memory.

## Enabling Work is not starting a run

Work starts off for a hat and needs permitted surfaces plus explicit identity-audience acknowledgement. A populated hat also requires admin review of its **entire historical memory**, including archived/superseded versions, in paginated views with full-snapshot count/fingerprint and identity fingerprint checks. Den fences the canonical snapshot, rechecks both fingerprints, and records a review receipt before enabling Work. Later eligible runs can read subsequent curated hat knowledge; enablement is not a per-run empty-memory test. Revoking Work or surfaces denies subsequent admission/effects. Neither enablement nor a hat grant supplies a Job, credential, tool, workspace, or network route.

## Hat access policy: partial effect cutover

Den owns Bear/hat-scoped action and normalized destination grants. Current supported intersections are:

- **Den web:** fetch/search check the live owner/member/source/hat, supported action and destination grants, and Bear blocks. Fetch can use an exact single-call/continuation URL approval; HTTPS-host persistence is an admin-only current-hat choice. Search requires the supported provider and host grant. DNS/private-IP checks, pinning, no redirects, and no ambient proxy apply.
- **Editor filesystem reads:** supported read-only descriptors can use an exact-root Den-owned grant after current owner/hat/root checks and a second check before effect. Admin ACP persistence is atomically tied to the winning obligation. Work, writes, commands, and MCP do not inherit it. Symlink checks are not race-free open-by-handle enforcement.
- **Work sandbox egress:** eligible runs receive the hat/surface host intersection; upgraded relays consult Den before each new external connection using the exact live run/token and provisioned ceiling. Revocation triggers cancellation/token revocation and retried teardown. Existing connections can last up to 60 seconds; this is not per-HTTP-request or instantaneous revocation. The optional provider's real Job/revocation flow remains unverified.

There is **no ordinary Legacy network or Cargo fallback**. Retained old approvals/helper behavior cannot admit an unbound ordinary source. The unrestricted Cargo helper is denied for hat-bound Work, and automatic Cargo preparation is denied during hat-bound Rust provisioning; those Jobs need a separately grant-enforced dependency cache.

This is **not a complete `HatGrantResolver`**: Den action/resource filtering remains partial across web, filesystem reads, and sandbox egress. Capability catalogs, broader Den effects (including Cabinet), provider upstream/git/credentials, and other client-tool families still need the common resolver. Supported ACP persistent choices do not generalize to other tools. Broader Den effects and other bounded `Always for [hat]` choices are next; [Gate 0A](../roadmap/HATS_AND_SESSION_MEMORY_BOUNDARIES_PLAN.md#gate-0a--hat-owned-tool-and-network-permissions-partial-cutover-exit-pending) owns that work.

## Internal operations

Curate briefings use a direct, dedicated inference path: a typed Reflection-run ID must resolve to a live running `memory_curate` source and its active Bear-owned reflection conversation, checked before inference and before text delivery. Tools and checkpoint tools are absent; unexpected tool requests fail. Worker briefings receive only the supplied rule-based briefing under that verified Reflection source. Instructions come through repository Markdown, not an ordinary stance registry or invented default hat. Generic system-origin starts, dispatch, results, and continuations are denied. Observation is a narrow worker/intake source, not a generic ordinary model session.

## Guarded identity deletion

**Code/test follow-on; not deployed:** operator user deletion now uses an explicit GET preview and session/target-bound expiring POST confirmation. The shared identity-deletion helper—not just the web button—locks the target User, then affected Bears in deterministic UUID order, rechecks remaining Admins and either deletes atomically or returns a typed blocker. Membership grant/demotion/revocation uses the same User-before-Bear order, including a User key-share lock, so a new grant cannot slip through the deletion snapshot or reverse the lock order. Preview is advisory; confirmation rechecks current state. No automatic ownership handoff or access elevation occurs.

A sole-Admin account must hand off every affected Bear first. Existing historical foreign-key restrictions remain intact; handing off membership does not authorize purging durable provenance. Operator views show affected Bear names and the owning membership-management route; anonymous users, members and Bear-only admins cannot use them. The account and memberships remain unchanged on denial. Application mutation paths are guarded; arbitrary privileged SQL is outside this application transaction contract.

## Bounded credential-mediated repository effect

**Code/mock tested, not deployed:** `repository_head` is descriptor-owned and Den-hosted, accepts only a managed repository UUID and returns that UUID plus a validated configured-branch SHA. Current source/actor/hat, exact action/resource/host ceilings and blocks, own attached Connection/current manager, revision/reference/version and exact Work run/Job are checked before credential lookup and before/after network I/O. Opaque references are not authority, and another human's credentials cannot be borrowed through Bear membership or admin transcript inspection.

A narrow `den-repository` adapter uses `secrecy`/`zeroize`, a fixed pinned GitHub HTTPS destination, bounded time/response size, no redirects/proxy/retries and closed output/errors. External-reference Connections are excluded from managed credential export/provisioning; queued/live/paused Work blocks replacement/detachment. Production deliberately reports `credential_unavailable` until a trusted external resolver is integrated, with no ciphertext/environment fallback. The new exact grant UI and Connection reference UI state that limitation; no KMS/backend/deployment choice was made.

Authenticated mock HTTP → real native dispatch → automatic persistence → fresh-turn Chat Completions and Responses requests prove business output/replay without canary or internal-reference bytes. Source/grant/owner/run revocation, mismatched scope/version, DNS/proxy/redirect/size/time/error echoes, canonical managed export and migration refusal tests cover this bounded effect. Genuine hosted-tool step handoff and shared model replay projections were corrected to exercise that actual path; historical diagnostic-only rows remain diagnostic. Broader resource enforcement, legacy credential files/environment/config/telemetry, complete exposure-matrix and live backend/provider acceptance remain pending.

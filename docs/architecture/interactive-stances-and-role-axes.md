# Interactive execution axes

Current working-tree WIP separates source authority from identity, resources, supervision, and derived labels. See [the maintained topic](../topics/bear-memory-hats.md) for verification limits; the latest image has not been rebuilt.

## Independent inputs

| Input | Question |
| --- | --- |
| Authenticated human and membership | Who is acting, and do they still belong to the Bear? |
| Canonical conversation or exact Work run | Which immutable source is owned/eligible now? |
| Real Bear-owned hat | Which identity, private/curated memory boundary, and applicable grants? |
| Verified origin and armature availability | Channel, browser task controls, connected/disconnected armature, eligible Job, or dedicated internal source? |
| Resources and credential actor | Which workspace, surface, network ceiling, and credentials can narrow access? |
| Governance | How is the current run supervised? |
| Current task or Work assignment | Which persisted objective can drive continuation? |
| Exact permission obligations | Which action/target is approved once or covered by a live bounded hat grant? |

Every ordinary conversation/Job/run requires a real hat, including zero-hat Bears. Pending IDE materialization follows admission; reconnect cannot invent a hat or switch the source. Old unbound history is owner/admin read-only. Inference, continuation, result recording, and direct dispatch recheck live actor/source/hat and exact Work eligibility.

## Channel, browser tasks, and armature

Channel conversations do not assume local tools. Browser task sessions have server-owned session-task controls without a local armature. Armature conversations can use client-local tools only while actual availability, governance, resource bounds, and obligations permit. A Write label, forwarded descriptor, or client-session hint does not create a harness. Disconnect narrows capabilities on the same immutable source; it does not turn a human conversation into Job authority.

## Governance and objective

`interactive`, `grace`, `autonomous_continuation`, `observational`, and `frozen` describe supervision. Canonically resolved session current tasks and exact Work assignments are separate objective owners. Cached task lists, prompt prose, and rendered activity cannot select them or force continuation. Restricted governance cannot silently become interactive at completion.

## Derived labels, not stances

The removal of `TrustProfile` / `BearProfile` / `BearStance` leaves derived runtime-context metadata (`RuntimeContextLabel`). Its five source-kind labels retain historical `chat/pair/work/curate/watch` schema/audit encoding. They are not configurable stances, live model/loop overrides, memory owners, or authority inputs. Browser-task origin remains distinct even though its label shares the historical armature spelling.

Internal Curate/observation operations use dedicated verified sources. Curate briefing is direct tool-free inference through repository Markdown instructions; generic system starts/tools/results/continuations are denied.
